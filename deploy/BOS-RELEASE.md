# Кэт и Штирлиц: размещение на NOWATER.TECH

Дата: 5 октября 2026.

2 агента работают в существующем кабинете, на том же серверном шлюзе и общих ключах платформы. По умолчанию используются OpenAI и `gpt-5` из конфигурации Никиты. Проверка общего ключа Anthropic при переносе вернула HTTP 401; новые агенты его не используют. Gemini доступен через прежнее общее подключение. Веб-поиск добавлен к запросам этих 2 агентов: Responses `web_search`, Anthropic server search и Gemini grounding. Число поисков Кэт ограничено 5, Штирлица — 30. API Replit, Replit DB и код внешних интеграций из архивов не включены в сборку.

## Промпты

`deploy/bos-prompts/manifest.json` содержит источники и SHA-256. `kat-main.txt` — основной сценарий из файла Кэт; 3 режима извлечены из строковых констант ее `main.py` без редакторских изменений. `stirlitz-main.txt` взят из отдельного пользовательского архива `shtirlits-BOS.zip`. В архиве Кэт также есть другая версия Штирлица: `stirlitz-chain-reference.txt` сохранен для сравнения и не включен в действующую конфигурацию.

Форма подставляет контекст в шаблоны на сервере. Дополнительное правило контекста находится в `src/lib/server-bos.ts`, отдельно от оригинальной методологии. Общее правило платформы с заголовками «Документ» и «Разбор и вопросы» выключено для этих агентов, чтобы сохранить исходный формат результата.

## Хранение

PostgreSQL 16 на Timeweb, БД `nowater`, роль `nowater_app`, только localhost. Параметры подключения: `/etc/nowater/database.env` (root:bezvody 0640), systemd drop-in сервиса `bezvody-front`.

`platform_documents` хранит настройки, участников, проекты, сообщения и метаданные вложений, с прежней структурой в JSONB. `platform_usage` хранит новые события расхода. Секреты и содержимое вложений остаются в приватном `/opt/bezvody-front-data` на Timeweb. Старые JSON-файлы после включения `BV_DATABASE_URL` не являются актуальным хранилищем: править нужно БД либо пользоваться кабинетом. При недоступной БД код не возвращается к устаревшим файлам или встроенному администратору.

Миграция: остановить приложение, сохранить резервную копию, выполнить `scripts/migrate-postgres.mjs import`, затем `verify` с переменными из `database.env`. Импорт атомарен и не перезаписывает существующие записи. `scripts/install-bos.mjs` добавляет только 2 новых агента и открывает их существующим администраторам. Доступ другим участникам назначается из обычной админки.

Резервные копии: `nowater-postgres-backup.timer`, ежедневно в 03:30 UTC. Содержат `pg_dump -Fc` и архив приватных файлов, доступны только root. Копии не удаляются автоматически.

## Откат

Остановить `bezvody-front`. Сначала выполнить `scripts/migrate-postgres.mjs export` с текущей БД и `BV_DATA_DIR=/opt/bezvody-front-data`, чтобы сохранить новые разговоры. Затем вернуть предыдущий bundle, убрать только добавленный drop-in `database.conf`, выполнить `systemctl daemon-reload`, вернуть владельца файлов bezvody и запустить приложение. PostgreSQL и копии данных не удалять. Для возврата состояния на момент релиза использовать отдельную резервную копию, учитывая новые записи после релиза.

## Проверки

- `npx tsc --noEmit` и сборка `NITRO_PRESET=node-server npm run build`.
- `tests/bos.test.ts`: режимы и контекст, отсутствие незаполненных переменных, сохранение нулей и пропусков в канве, ссылки, изоляция секретов от БД.
- Импорт и сверка 50 исходных документов на отдельной PostgreSQL-базе, обратный экспорт и повторная сверка.
- Проверка отказа доступа при недоступной БД без возврата к JSON/встроенному администратору.
- Реальный браузерный сценарий и платные вызовы моделей проверяются на публичных/синтетических данных.
